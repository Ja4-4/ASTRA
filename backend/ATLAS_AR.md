# Atlas داخل الباك اند (ASTRA)

Atlas هو المساعد الصوتي/النصي. هذا الملف يشرح كيف يتصل بالباك اند، وماذا يقدر يسوي، وكيف يستعمله الفرونت.

## كيف يشتغل

```
المستخدم (كلام/نص)
   → POST /api/atlas/command
        1. الباك اند يختار أقرب 5 أوامر من القائمة (29 أمر) ويعرضها على النموذج
        2. النموذج (Qwen2.5-0.5B المضبوط) يرد JSON: {reply, lang, action}
        3. الباك اند يتحقق من كل شيء (الأمر ضمن المعروض؟ القيم صحيحة؟ الأرقام والمؤشر مذكورة في كلام المستخدم؟)
        4. قراءة → تنفذ فوراً | كتابة → ترجع رمز تأكيد | واجهة → تعليمة للفرونت
```

النموذج **يقترح فقط**. هو ما يلمس قاعدة البيانات، ولا يعرف المسارات. الباك اند هو اللي ينفذ، وبصلاحيات الرائد المرسل في الطلب.

## التشغيل

1. شغّل خادم النموذج على الجهاز (ويندوز، مجلد `medical_500m`): دبل-كلك على `run_atlas_server.bat`. يفتح `http://127.0.0.1:1234/v1`.
2. شغّل الباك اند بهذي المتغيرات:

```
set ASTRA_AI_PROVIDER=openai
set ASTRA_AI_URL=http://127.0.0.1:1234/v1
set ASTRA_AI_MODEL=ai
cargo run --release -- serve
```

3. تأكد: `GET /api/atlas/status` لازم يرجع `"reachable": true` و`"model_installed": true`.

متغيرات اختيارية: `ASTRA_ATLAS_REGISTRY` (مسار قائمة أوامر ثانية)، `ASTRA_AI_TIMEOUT_S` (افتراضي 120).
بدون الخادم، كل الباك اند الباقي يشتغل عادي، وأوامر Atlas ترجع خطأ واضح.

## المسارات

| المسار | الوظيفة |
|---|---|
| `GET /api/atlas/status` | حالة القائمة والنموذج وعدد التأكيدات المعلقة |
| `GET /api/atlas/actions` | قائمة الأوامر الـ29 (للعرض أو التوثيق) |
| `POST /api/atlas/command` | `{"message": "...", "astronaut_id": 1}` ← رد Atlas |
| `POST /api/atlas/confirm` | `{"token": "...", "approve": true}` ← تنفيذ أو إلغاء كتابة معلّقة |

## حالات الرد (`status`) من `/command`

| الحالة | المعنى | وش يسوي الفرونت |
|---|---|---|
| `chat` | كلام عادي بدون أمر | يعرض `reply` ويقرأه صوتياً |
| `executed` | تم تنفيذ قراءة | يعرض `reply` + `result` (نفس JSON مسارات `/api/...`) |
| `needs_confirmation` | كتابة تنتظر موافقة | يعرض `confirm.summary`، وإذا وافق: `POST /confirm` بالرمز `confirm.token` (صالح 120 ثانية، مرة واحدة) |
| `ui` | تعليمة للواجهة | ينفذ `ui` (انظر تحت) |
| `needs_clarification` | قيمة ناقصة أو غير مؤكدة | يعرض `reply` (سؤال) |
| `error` | فشل | يعرض `reply` |

كل رد فيه `disclaimer` و`candidates` (الأوامر اللي شافها النموذج) و`elapsed_ms`.

## تعليمات الواجهة (`status = "ui"`)

الباك اند ما يغيّر الشاشة. يرجع `ui: {op, args, ...}` والفرونت ينفذها:

| `op` | الحقول | المطلوب من الفرونت |
|---|---|---|
| `navigate` | `route` (من `/`, `/log`, `/events`, `/evidence`, `/trends`, `/routine`, `/crew`, `/eye`) | ينتقل للصفحة |
| `set_theme` | `args.mode` = `dark` أو `light` | يغيّر المظهر |
| `set_language` | `args.lang` = `ar` أو `en` | يغيّر اللغة |
| `select_astronaut` | `astronaut_id`, `display_name` | يختار الرائد |
| `stop_speaking` | — | يوقف القراءة الصوتية |

## الأوامر الـ29

- **قراءة (17، تنفذ فوراً):** ملخص الحالة، آخر قراءة، اتجاه مؤشر، التنبيهات الحالية والسابقة، الأحداث وتفاصيل حدث، الروتينات، قراءة البيئة وتقييمها ونموذجها، المصادر العلمية، قائمة الرواد، ملفات الاستيراد وسجله، سجل العين ونموذجها.
- **كتابة (7، تحتاج تأكيد):** تسجيل قياس، اعتماد تنبيه، إكمال روتين، فتح حدث، إكمال متابعة، إضافة رائد، استيراد بيانات.
- **واجهة (5):** تنقّل، مظهر، لغة، اختيار رائد، إيقاف القراءة.

## الأمان

- أي أمر يغيّر بيانات لا ينفذ إلا بعد تأكيد المستخدم صراحة (رمز عشوائي 32 خانة، مرة واحدة، 120 ثانية).
- النموذج ما يقدر ينفذ أمراً ما انعرض عليه، ولا مسار خارج القائمة المسموحة (`/api/atlas` و`/api/ai` و`/api/eye/analyze` ممنوعة).
- رقم الرائد يجي من الطلب، مو من النموذج. التنبيهات والروتينات والأحداث تتحقق من ملكية الرائد.
- القيم لازم تطلع من كلام المستخدم: رقم ما قاله المستخدم، أو مؤشر يناقض اللي ذكره، يتحول إلى سؤال توضيح.
- كل تنفيذ مسجّل في `data/atlas_audit.jsonl`.

## حدود النموذج (بصراحة)

النموذج صغير (0.5B). على 610 عينة اختبار بصياغات ما شافها: اختيار الأمر الصحيح **71%** (إنجليزي 82%، عربي 63%، مختلط 59%)، JSON صالح 95%، أمر وهمي 0.3%. أضعف نقطة: يرفض أمراً يعرفه، أو ينفذ أمراً قريباً بدل ما يقول "غير متاح". لذلك الكتابة كلها بتأكيد، والقيم تتحقق من كلام المستخدم، والأرقام على الشاشة تبقى هي المرجع. المساعد ما يشخّص ولا يصف جرعات.
